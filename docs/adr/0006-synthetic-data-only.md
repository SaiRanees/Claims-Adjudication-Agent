# 0006. Use synthetic data only

- Status: Accepted
- Date: 2026-11-11

## Context

This is a portfolio project that will be public. Real health claims carry sensitive personal data: diagnoses, bills, identity documents. The author also works on insurance systems in a day job, so the line between this project and that work has to be unmistakable.

## Decision

The repository and every environment use synthetic data only. Members, policies, bills and discharge summaries are generated by `cmd/datagen` or written by hand, and are marked as synthetic. There are no real claims, patients or policyholders, and no code, data, documents or configuration from any employer or client.

The rule pack is built from the insurer's publicly available policy wording and cites it by UIN. Model providers only ever receive synthetic documents.

## Consequences

- The repository can be public, demos can be recorded, and logs and traces are safe to share.
- Evaluation quality depends on how realistic the synthetic documents are, so the generator has to cover the messy cases: scans, handwriting, multi-page bills, missing pages.
- Using any real data later would need a new ADR, consent from the people concerned, and a review against India's Digital Personal Data Protection Act, 2023.

## Alternatives considered

- **Anonymised real claims.** Health records are hard to anonymise reliably, and they could not be published.
